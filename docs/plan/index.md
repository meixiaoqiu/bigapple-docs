# 建设计划

> **状态：讨论草案**
>
> 本文是大苹果社区总体建设路线的框架说明，描述"准备怎样做"。它不构成投资邀请、股份认购或公司对任何人的承诺。实际执行方案需经过相应决策程序和专业审查。

## 这份计划解决什么问题

大苹果社区不是单纯的软件项目。

Big Apple Live OS 是支撑社区运行的信息工具，但它本身不能代替现实社区。要从理念和代码走向真实运行的共同生活社区，还需要解决制度、人员、组织主体、资金、场地和实际运营等一系列问题。

本页负责把这些工作放入同一条建设路径中，说明它们的先后关系、阶段目标和进入条件。它不是 Live OS 产品路线图，也不是已经生效的治理制度。

## 当前所处阶段

大苹果社区目前主要处于以下工作：

- **理念和规则持续整理**：将分散的讨论整理为结构化的治理文书和运行制度；
- **文档体系建设**：建立公开可访问的文档站，使规则、术语和建设路径可以被外部理解；
- **Live OS 开发**：建设支撑成员、任务、资源、治理和审计的软件系统；
- **仿真与制度验证**：在投入现实资源前，通过推演和仿真暴露制度缺陷；
- **现实组织方案研究**：研究法律主体、成本模型和首个园区的可行性。

同时需要明确：截至目前——

- 尚未成立本计划拟议的社区运营公司；
- 尚未正式招募公司发起人；
- 尚未启动股份认购或收款；
- 尚未确定第一个现实园区。

## 总体建设原则

以下原则用于指导各阶段的推进：

- **先验证，后扩大**：每个阶段都应在有限范围内验证通过后，再考虑扩大规模；
- **先形成可审计规则，再处理真实资金**：涉及资金之前，必须有公开的预算、审批和审计规则；
- **社区、公司和 Live OS 相互配合，但不混为一体**：社区是共同生活体，公司是法律运营主体，Live OS 是信息工具，三者各有边界；
- **软件开发不能代替现实运营验证**：仿真和软件测试可以发现部分问题，但不能替代真实环境中的人员、资金和制度检验；
- **每个阶段都应有明确进入条件**：进入下一阶段前需满足公开的前置条件，不靠临时判断跳过；
- **法律、财务、税务和安全问题须经专业审查**：涉及法律主体、资金、人员安全和不动产的事项，不能仅由内部讨论决定；
- **失败、暂停和回退也是计划的一部分**：如果某个阶段验证失败或条件不满足，应暂停或回退，不应强行推进；
- **计划、已生效制度和历史记录分别管理**：建设计划说明"准备怎样做"，已生效制度说明"应当怎样做"，建设动态记录"已经做了什么"。

## 总体建设阶段

以下六个阶段描述大苹果社区从当前状态走向现实运行的大致路径。阶段可以调整、拆分或合并，不因目前的划分而锁定所有未来安排。

### 阶段一：理念、术语与基础规则整理

**当前状态：正在进行**

目标：

- 明确社区要解决的核心问题；
- 统一关键术语的定义和边界；
- 把直觉和零散讨论转化为可公开讨论的规则草案；
- 建立结构化的公开文档体系，使外部人员能够独立理解项目。

进入下一阶段的条件：

- 核心概念能够被不熟悉项目的人独立理解，不需要口头解释；
- 重要规则不再只存在于少数参与者的个人认知中，而是以文档形式公开可见；
- 术语体系足以支撑后续的成本模型、仿真和制度讨论。

### 阶段二：成本与运行模型验证

**当前状态：尚待研究**

目标：

- 研究共同生活在不同规模下的最低运行成本；
- 验证住房、食物、任务分工、贡献积分和资源分配模型之间的数量关系；
- 识别法律、财务、税务和运营层面的主要风险；
- 通过纸面推演和初步仿真暴露模型中的明显缺陷。

进入下一阶段的条件：

- 完成基本成本模型，其假设、数据来源和局限性已被明确记录；
- 运行模型中的关键环节（如积分发行、任务定价、资源分配）已通过推演检验，不存在显而易见的逻辑漏洞；
- 主要法律和财务风险已被识别，并且不存在无法解决的根本性障碍。

本阶段不预设具体金额。成本数字将在专项计划中根据实际调研填入。

### 阶段三：Live OS 与仿真工具建设

**当前状态：正在进行**

目标：

- 建设支持成员管理、任务分配、积分记录、资源调度、治理投票和审计追溯的软件系统；
- 使用仿真工具在长期运行假设下检验制度的稳定性，提前暴露分配失衡、积分通胀或治理僵局等问题；
- 明确软件只是辅助工具，不代替现实中的制度判断和人员决策。

本阶段的详细内容见：

- [Live OS 产品规划](../project/product-planning.md)——软件系统的中远期功能设计和用户角色；
- [Live OS 产品路线图](../project/roadmap.md)——软件系统的分阶段开发计划；
- [仿真与实验后台](../product/simulation.md)——仿真分层、数据模型和工程规则。

### 阶段四：现实组织主体与创世参与者形成

**当前状态：尚待研究**

目标：

- 研究并确定适合大苹果社区长期运行的法律组织主体形式；
- 形成公司设立计划，明确成立目的、治理结构、资产归属和公司与社区的边界；
- 明确创世发起人的资格条件、遴选方式和责任义务；
- 完成设立前必要的法律、财务和税务审查。

进入下一阶段的条件：

- 公司设立计划已经完成，关键法律问题已获得专业意见；
- 发起人候选人已按照公开标准形成，且候选人已经充分了解其权利、义务和风险；
- 必要的法律文件、章程和协议草案已经准备，可供审查。

本阶段只写总体目标，具体股份类别、融资金额、发起人人数和出资方案将放入专项计划。

### 阶段五：首个现实园区筹备与试运行

**当前状态：尚待研究**

目标：

- 制定选址标准，包括地理位置、交通、住房条件、安全、消防和公共服务配套；
- 核算真实预算，包括租金或购置成本、改造费用、运营成本和应急储备；
- 确保安全、消防、卫生和住房条件符合适用法律法规的最低要求；
- 形成首批入住方案，明确入住条件、退出机制和试运行期间的特别规则；
- 在小范围内试运行，在有限风险下检验制度、成本和人员协作的实际效果；
- 保留在试运行阶段停止、调整或退出的条件。

进入下一阶段的条件：

- 选址已确定，相关法律文件（如租赁或购置合同）已签署；
- 安全、消防和卫生条件已通过必要的检查或专业评估；
- 试运行期间的规则、预算和应急方案已经准备；
- 所有参与者已被告知试运行的性质、风险和退出条件。

本阶段不假定已经存在具体园区。

### 阶段六：公开验证、修订与有限扩展

**当前状态：尚待研究**

目标：

- 公开首个园区的运营数据和审计结果；
- 对制度、成本模型和软件系统进行全面复盘；
- 修订在试运行中暴露问题的规则；
- 只有在首个园区证明可持续运行后，才讨论是否以及如何复制和扩大。

进入本阶段的条件：

- 首个园区已经完成一个完整周期的试运行，并且财务和治理记录可供审计；
- 关键指标（如成本可承受性、成员稳定性、制度有效性）已经过评估；
- 制度修订程序已经完成，试运行中发现的问题已有对应的规则修正。

本阶段不预设必然扩张。是否复制、以何种方式复制，取决于首个园区的实际验证结果和当时社区的集体决定。

## 各专项计划之间的关系

总体建设计划未来将包含以下专项计划。每份专项计划回答一个具体领域的问题，共同构成完整的建设路线。

| 专项计划 | 主要回答的问题 |
| -------- | -------------- |
| [公司设立计划](./company-formation.md) | 为什么需要成立公司、采用何种形式、怎样依法设立 |
| [首个园区分期建设方案](./first-campus.md) | 开荒、建设、扩容和达到设计容量的分期方案 |
| 创世发起人形成计划 | 谁可以成为发起人、需要满足什么条件、如何遴选 |
| 资金与财务计划 | 资金从哪里来、怎样预算和使用、如何审计 |
| Live OS 产品路线 | 软件系统准备怎样分阶段建设和交付 |
| 仿真验证计划 | 怎样在现实实施前通过仿真暴露制度和流程问题 |
| 法律与合规计划 | 哪些事项需要专业审查、审查的范围和标准 |
| 公开审计计划 | 资金、资产和决策记录怎样保持透明和可追溯 |

以上专项计划除公司设立计划和首个园区分期建设方案外均尚未编写。它们的名称和范围可能随讨论调整。

## 当前未决问题

以下问题目前尚未确定，需要后续研究和讨论：

- 最终采用何种法律组织主体和公司结构；
- 公司与社区治理之间如何衔接，各自权限如何划分；
- 创世发起人如何形成，遴选标准和程序如何设定；
- 首个园区的规模、选址标准和最低安全条件；
- 现实运行前需要完成哪些专业审查，审查结果如何影响推进决策；
- 仿真达到什么标准才能认为制度已准备好进入现实试验；
- 如何定义每个阶段的成功、失败、暂停和回退条件。

这些问题将在对应的专项计划中逐项研究，不在本页直接给出未经确认的结论。
